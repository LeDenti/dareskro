# dareskro × Solana — Developer feedback

Context: Anchor program `dareskro_escrow` on devnet ([`6NoVNiHv…`](https://explorer.solana.com/address/6NoVNiHvEsagkYYobHjrwQgkqL5xHp5zGStZK4YtdPSu?cluster=devnet)), ownerless PDA escrow (SOL/USDC), time or hash lock, non-transferable Token-2022 payslip, Aurora Intents.

1. **Token-2022 extension mints can jam the vault** *(code review, not an on-chain measurement)* — Since the stray-unit fix, the program pays out the vault's real balance and requires it to cover the recorded amount (`VaultShort`, [`programs/dareskro_escrow/src/lib.rs` l.184](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/programs/dareskro_escrow/src/lib.rs#L184) and [l.229](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/programs/dareskro_escrow/src/lib.rs#L229)). With TransferFeeConfig the vault receives less, so payout *and* refund fail on this guard, not on the transfer itself. PermanentDelegate lets a third party drain it; there is no mint-extension check. Proposal: a standard Anchor constraint to reject extensions, or an official "safe escrow with Token-2022" guide.
2. **Stray-unit vault griefing** — anyone can send 1 unit, so `close_account` fails and the account rent stays locked. Evidence: repro test [`tests/dareskro_escrow.ts` l.354-355](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/tests/dareskro_escrow.ts#L354-L355); fix [`lib.rs` l.183](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/programs/dareskro_escrow/src/lib.rs#L183) and [l.228](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/programs/dareskro_escrow/src/lib.rs#L228) (pay out the full vault balance). Proposal: document in Anchor escrow examples; offer a sweep-and-close helper.
3. **Aurora Intents: no testnet, persistent deposit address gated** — Aurora ran live on mainnet on 1 November at 07:44 UTC (08:44 Paris) with the dareskro key from their portal (XRP → 3 USDC in 37 s: [XRPL 56205926…](https://livenet.xrpl.org/transactions/56205926A4B9F65FBE7775F7607D4D568F94995BEF722731577B721C3C74A1E1), [Solana 58Az4DDm…](https://solscan.io/tx/58Az4DDmpE9MQBMfKjw6bU4SFNuPDkmF1mW1EF2qjaZV6K3W1VMDpXToJZjm7HoKw8bUm4MfyNjyKuQ4x9oguQ9g); [README l.221-232](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/README.md#L221-L232)); the client's DRY mode ([`client/aurora_intents.mjs` l.145](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/client/aurora_intents.mjs#L145)) is our choice, not an Aurora constraint. Real limits: no testnet, and the persistent deposit address requires an approved organization (403 otherwise: [README l.202](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/README.md#L202); no testnet: [l.205](https://github.com/LeDenti/dareskro/blob/58228d15b0f737d89088819512e4e380a86c774b/solana/README.md#L205)). Impact: every real run spends real mainnet funds (a quote is free); an employer cannot get a stable payroll deposit address without approval. Proposal: a testnet/sandbox; a clearer approval path and a documented 403 (reason + next step).
