# dareskro × Casper — Developer feedback

Context: Odra 2.10.0 contract [`contract/src/escrow.rs`](contract/src/escrow.rs) (escrow with a date lock, a SHA-256 condition, a refund date and a fee capped at 1 %), installed on `casper-test` on 7 November 2026 and driven from Node with `casper-js-sdk` 5.3.1 ([`dareskro_casper.mjs`](dareskro_casper.mjs)). 14 tests on OdraVM and CasperVM, 23 testnet steps. Every item cites a transaction, a line or an upstream file; what was not measured says so. Upstream facts were re-read on 14 November 2026 (Odra tag `2.10.1`, `casper-client-rs` `v5.0.1`, testnet node 2.2.4).

1. **The published Odra crates still ship the 184 KB proxy caller.** Odra PR [#648](https://github.com/odradev/odra/pull/648) (merged 9 June 2026) shrank `proxy_caller_with_return.wasm` from 184 KB to 41 KB. At tag `2.10.1`, and on `release/2.11.0` on 14 November, the root `resources/` and `odra-wasm-client/resources/` hold the 41 012-byte file, but `odra-casper/rpc-client/resources/` and `odra-casper/test-vm/resources/` still hold the 184 758-byte one, and so does the `odra-casper-rpc-client` 2.10.0 crate on crates.io, which is where we took it. Effect, measured: our payable `create` ([f64a769b…](https://testnet.cspr.live/transaction/f64a769b9668be726b5587a1e52f4fcfa577ad0ed65c601d54ab27d1c90b2252)) has a `size_estimate` of 185 585 bytes; the testnet chainspec gives Wasm lane 5 a 65 536-byte limit (40 per block), lane 4 131 072 bytes (2 per block) and lane 3 750 000 bytes (**1 per block**), so the call only fits lane 3. *Not measured:* the same call with the 41 KB file. Proposal: one source for the file, or a CI check that the copies match.
2. **The TypeScript tab of "Using Proxy Caller" is on the legacy SDK and names an argument the proxy does not read.** The [tutorial](https://odra.dev/docs/tutorials/using-proxy-caller) (last updated for 2.10.0) uses `CasperClient`, `Contracts`, `RuntimeArgs`, `CLValueBuilder` and `putDeploy`, the `casper-js-sdk` 2.x Deploy API, and passes `contract_package_hash`. Odra 2.10.1 reads `package_hash` ([`core/src/consts.rs` l.31](https://github.com/odradev/odra/blob/2.10.1/core/src/consts.rs#L31)). The same call on `casper-js-sdk` 5.3.1 (`SessionBuilder`, `Args`, `CLValue`), with `package_hash`, executed on testnet (tx above; [`dareskro_casper.mjs` l.114-131](https://github.com/LeDenti/dareskro/blob/b5927a9/casper/dareskro_casper.mjs#L114-L131)). *Not measured:* that `contract_package_hash` fails. Proposal: update the tab; our 18 lines are free to take.
3. **A reverted transaction gets no refund, and the public RPC cannot estimate gas.** A refused `release` ([a88caa4f…](https://testnet.cspr.live/transaction/a88caa4fdb885915b9dae86858f3767cc11e1ad50d2386e4a0eb31076f189dfe), `User error: 3`): limit 5 CSPR, consumed 0.0173 CSPR, cost 5 CSPR, **refund 0** — about 290 times what it consumed. An accepted `release` ([a3450057…](https://testnet.cspr.live/transaction/a34500571ce81cfd8d291e5d34d48fbd533cd8e9cb4e6c1d2f25b3a9065a6646)): consumed 3.116 CSPR, refund 1.413 CSPR, which is the chainspec's 75 % of the unused part. On the public testnet endpoint (2.2.4), `rpc.discover` lists 25 methods and none simulates; `speculative_exec` and `speculative_exec_txn` answer `-32601 Method not found`. So a client must guess the limit, keeps paying 25 % of its over-estimate on success and all of it on a revert. Our first pass stopped when a test account ran out of funds partway through the refusals ([README l.107-108](https://github.com/LeDenti/dareskro/blob/b5927a9/casper/README.md#L107-L108)). Question: is the zero refund on revert intended? Proposal: apply the refund ratio to reverted transactions, or document the rule next to `refund_handling`; say where a simulation endpoint can be reached.
4. **`casper-client` has no prebuilt binary, and a missing entry point is not an error.** The four latest releases (`v4.0.0` to `v5.0.1`) carry no asset; `cargo install casper-client --version 5.0.1 --locked` took about 20 minutes on an Apple-silicon Mac. `--session-entry-point` is declared `.required(false)` ([`creation_common.rs` l.1177](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L1177)) and the four subcommands that call an entry point read it with `unwrap_or_default()` (l.2175, 2227, 2290, 2349), so an absent value becomes an empty name, as the community guide [`casper-client-5.md`](https://github.com/msanlisavas/casper-llms/blob/main/guides/casper-client-5.md) says. *Not hit by us:* we always passed it. Proposal: release assets for Linux and macOS; make the argument required on the subcommands that need it.
5. **`User error: N` is decoded by hand, and reading a field means recomputing Odra's dictionary key.** Our client keeps its own table of 13 codes ([l.77](https://github.com/LeDenti/dareskro/blob/b5927a9/casper/dareskro_casper.mjs#L77), [l.92](https://github.com/LeDenti/dareskro/blob/b5927a9/casper/dareskro_casper.mjs#L92)) and derives `blake2b(index ++ key)` itself to read an escrow without a transaction ([l.165-178](https://github.com/LeDenti/dareskro/blob/b5927a9/casper/dareskro_casper.mjs#L165-L178)). The layout is documented upstream ("Reading the storage from the outside", storage layout article), which we found afterwards. *Not tried:* `odra-wasm-client`, which has `call_payable_entry_point` and the 41 KB proxy but whose example targets the browser and CSPR.click. Proposal: say in the docs whether `odra-wasm-client` runs under Node with a key file; otherwise a small JS helper that reads the contract schema Odra generates (errors and fields).

## Corrected on our side, 14 November 2026
- We first wrote that the payable call through the proxy caller was documented nowhere. It is: Odra's tutorial above, and the Casper backend page. What is out of date is its TypeScript tab (item 2) and the file the crates ship (item 1).
- Item 5 first read as if reading the state were undocumented. Odra documents the layout; what is missing for a JavaScript client is an example.

## Questions, not findings
- Does a wasm built against the 1.x `casper-contract` crate run on 2.x? We recompiled and never tried; the community assistant has no verified answer either.
- Is there a CEP-18 stablecoin in real use on Casper? An escrow in CSPR carries exchange risk for a salary or an invoice.
- Ledger signing on Casper 2.x: not tested by us.
